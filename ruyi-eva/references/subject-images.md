# 主体图

分镜里每个进镜的 `@图片n` 确认前都要有图。成片模型只认这些参考图：人脸、商品外观、场景都靠它们锁住，文字描述锁不住。分镜图、换装图都是新的 `@图片n`，没有另一条帧轨。

## 先选已有图，缺了才生

按顺序找：

1. **人设指针**：角色 face（`personas[].faceAssetId`）、常驻场景（`unit.world.scenes[].assetId`）、音色（`voiceAssetId`）。
2. **单元库**：`get_unit.assets` 里的 face / scene / prop。同一角色可能有多张图，先读 `description`；道具同名取最新一条。
3. **商品库**：`commerceProducts[].images`。先读每张 `label` / `description`，只挂适合这一条的那张。
4. **用户这次给的图**：先读用户原话决定用途（见下表），再上传。
5. **你自己生成**：上面都没有，或用户说「按这张生」才生。

本条已经挂过的图在 `get_content_context.subjectAssets`（带 `subjectLabel`），重生前先看有没有。

## 用户给了图，怎么处理

| 用户意图 | 做法 |
| --- | --- |
| 「用这张当 @图片n / 本条用这个道具 / 商品图」 | 上传 → attach 到那个编号 |
| 穿搭参考、「让主角穿这件」，图里**有人** | 不要直接挂原图（模特的脸会进成片）。走换装静帧 |
| 穿搭参考，图里**没人**（平铺、挂拍） | 上传 → 写成 `kind=style` 的新主体 → attach |
| 「换成这张脸 / 换主角」 | 不做。告诉用户「人脸不能换，请到平台人设页处理」 |
| 意图不清 | 先问用户这张图用来干什么，不要猜着绑 |

## 什么能生、什么不能

| 缺的是 | 怎么办 |
| --- | --- |
| 主角没有 face | **不生**。请用户去平台人设页补 |
| 商品图 | **不生**，只用商品库真图。缺图请用户上传或回平台选品 |
| 场景图（单元没有这个场景） | 可以生一张完整环境，挂到本条的场景主体。只属于这一条；要成为常驻场景请用户去平台人设页 |
| 道具 / 宠物 / App 界面等非人设主体 | 可以生，挂到本条主体 |
| 主角穿某件衣服（换装） | 可以生，**必须**带主角 face 作参考 |
| 主角在某个情境里的分镜图 | 可以生，**必须**带主角 face 作参考，见下文「分镜图」 |

你的生图工具不能输入参考图时：只生场景 / 道具这类不含人物的图，人物相关的图一律不生，直接用 face 原图。

## 自己生图的步骤

1. **下载参考图**：从 `get_unit` / `get_content_context` 拿 `url`（约 1 小时有效，过期重新调用），存到 `ruyi/<contentItemId>/refs/`，例如 `refs/face-coco.jpg`、`refs/outfit.jpg`。
2. **生成**：用你自己的生图能力，参考图作为输入图传入。存到 `ruyi/<contentItemId>/images/<label>-<短名>.png`。画幅一般用竖图（9:16 或 3:4）；一张图只画一个主体。
3. **自己检查**：脸是不是还是主角、有没有多出第二张脸、有没有文字水印、商品有没有变形。不合格就重生，不要挂上去。
4. **上传并挂表**（见 workflows.md「上传图片的固定动作」）：`create_upload` → PUT → `complete_upload(label, description)` → `attach_subject_image(subjectLabel=…)` → `get_storyboard` 刷新本地文件。
5. 生了多张、要花用户较多时间时，先把图给用户看一眼再挂。

`complete_upload` 的 `description` 写这张图**看得见的特点**，给以后选图用，不要抄 prompt。

## 主体图 prompt

用中文写，专名可留原文。一张图只写一个主体：正面、干净背景、无文字、无字幕。写清：

- 是谁 / 是什么：品种、年龄段、材质、颜色
- 固定标识：项圈、发型、包装色、Logo 位置
- 一个气质词；不写成片动作

例：`American Bully，黑毛白胸，坐姿，干净背景，无文字。`

场景图写成一张完整环境：地点、时段光线、几件标志性陈设，不放人物，不要九宫格。

## 换装静帧（图里有人的穿搭参考）

1. 表里写一个 `kind=style` 的新主体：`name` 用衣服短名，`usage=换装静帧`，`source=reference_only`，`referenceAssetIds=[]`。相关镜的 `shotPrompt` 写「`@图片1` 穿 `@图片n` …」，并把 `@图片n` 加进 `subjectLabels`。
2. 下载主角 face 和用户的衣服图，两张都作参考输入，prompt：

   `保留衣服参考图里的服装、姿态和身体。只把头部和脸换成主角。画面里只有一个人，不要第二张脸，干净背景，无文字。`

3. 检查脸是主角、只有一个人。上传 → `complete_upload` → `attach_subject_image(subjectLabel=@图片n, subjectKind=style)` → 刷新。
4. 不要把用户原图直接挂上，也不要为这件衣服再开一个 person 主体。

## 分镜图（主角在某个情境里的静帧）

用户要某一镜的分镜图，或你判断某镜构图 / 造型靠文字锁不住时才生。

- 写成 `kind=style` 的新主体（造型 / 构图参考，不是第二个人），`usage=分镜图`。该镜同时保留人设 `@图片1`，`shotPrompt` 写「`@图片1` 按 `@图片n` 的造型和构图 …」。
- 生成时带主角 face 作参考，画面里只有主角一个人，无文字。
- 只给真正需要的一两镜生，不要每镜都配一张：参考图越多，成片越容易串脸。

## 挂图规则

- `attach_subject_image` 按 `subjectLabel` 钉图：表里已有这一行（非人设）就原地把 `referenceAssetIds[0]` 换成新图；没有这一行就追加一个新主体，但**不会**写进任何镜，你要刷新后自己把它加进相关镜的 `subjectLabels` 和 `shotPrompt` 再保存。
- 推荐顺序：第 1 版就把要生图的主体行写好（`reference_only`），图到了再 attach 到这个编号，不用再改镜。
- 人设主体（带 `personaId` 的 person）attach 会被拒，人脸不能换。
- `subjectKind` 只在追加新行时用：`person`（非人设的活体，如宠物）、`product`（静物道具）、`style`（穿搭）。场景图请先在表里写好 `kind=scene` 的行，再按编号 attach。
- 单段最多 30 张参考图（成片接口上限）。超过就请用户少挂几张。
